## Phase 1 — What makes adilet's approach distinctive

| Area | Observed [your notes] | My read [assumption] |
|---|---|---|
| **First 3 seconds** | The first word is a stake (money, views, followers), and the topic comes second. Hook resolves in ≤1.5s. | The stake answers "why should I care?" before the viewer knows the topic. The topic then shows up as the explanation. |
| **Rhythm** | Only about 4–13 hard cuts per reel, but a new visual event on **every stressed word**, and nothing stays still for more than 1.2s. | The pacing comes from small changes (layers, stamps, counters) on a stable frame, not from cuts. That's why it feels fast but stays readable. Avg shot length is unmeasured, so this needs the recordings. |
| **Type & colour** | Clean grotesk, black on cream paper, accent words in red italic serif. A full red or black frame only for "the turn." | Restricting colour is what makes the turn hit. If everything is loud, nothing is. |
| **Composition** | VO text builds at the top, the illustration sits in the middle, the persistent 2D host is bottom-centre. HUD: chapter tag at top-left, escalating counter at top-right. | Fixed zones mean the viewer never has to search the frame, so comprehension holds at speed. |
| **Motion** | The illustration lands on its word. | Probably short eased pops and slides, with few transitions. Unverified. |
| **UI / diagrams** | File trees, `scenes.tsx`, skills and Remotion-style scenes all appear on screen. | Showing the real artefact (a file, a folder) makes "system" concrete and believable. |
| **Making tech simple** | "The secret isn't X, it's 1 folder" → 3 numbered rules → watch it build → why it works. | Reframing to one object (a folder), then a numbered framework, makes the idea feel ownable. |
| **Saves / shares / follows** | The keyword delivers real files, and the caption often holds the full prompt. One template means the grid reads as one show. | Saves come from "I'll need this later" (the prompt in the caption). Follows come from "this is a series." Shares come from the slightly scary stakes (getting sued, money). |

**Borrow (principles):** stake-first hooks · picture-on-word timing · fixed screen zones · one escalating number · numbered frameworks · a real deliverable behind the keyword · one template across the grid.

**Avoid (his signature, not ours):** cream paper with red italic serif · a cartoon host · his exact HUD phrasing (`// 03 · step one`) · his script skeleton line for line · his niche framing ("I help people make viral reels"). If Kai looks like an adilet reskin, the borrowed credibility turns into "copycat" in the comments.

## Phase 2 — Kai's current content and systems

**Working (keep):**
- **A real-looking persona with fixed traits:** glasses, handheld mic, seasonal themed mics. adilet has no equivalent, and the themed mics are a recognisable signature.
- **The "real answers only" rule** and the AI Dilemma format, when the AIs genuinely disagree.
- **The multicam trick** (one VO, many synced angles). It's a real production advantage, and cheap variety.
- **The honest AI-creator angle.** "I'm an AI, here's the system" is something only Kai can say truthfully.
- **The pipeline itself** (HeyGen, Higgsfield, Remotion, Claude Code) is the content. Kai can show it.

**Feels generic:**
- **News recaps** ("X just released Y"). Anyone can make them, and they don't hold value after day 1.
- **Label hooks** ("5 Claude skills that write for you").
- **Illustrating the noun instead of the action:** cards with skill names rather than the skill doing the work.
- **"Follow for more AI tools."** It gives the viewer no reason to act.
- **Five cover styles on the grid,** and a bio with no promise.
- **Mood b-roll** (stock-like hands and phones) standing in where a real screen recording would prove the point.

**Improve:**
- Every video should end with something the viewer can **use**: a prompt, a file or a checklist.
- Replace "here's news" with **"I tested it, here's the result."** That is literally Kai's tagline, and it isn't on screen yet.
- Treat one number per video as the spine: time saved, files, views, cost.

## Phase 3 — A distinctive Kai style: "Kai's Test Bench"

**Idea:** Kai's tagline is *"I test AI every day so you don't have to."* So every video looks like a **test report**: a hypothesis, the setup, a run of real footage, and a **verdict**. adilet's world is a design notebook; Kai's world is a lab bench. Same clarity, different identity.

| Element | Kai version |
|---|---|
| **Background** | Off-white with a faint **graph-paper grid** (a lab notebook), not plain cream. Dark mode for night or "the turn": near-black with a yellow grid. |
| **Accent** | **Yellow #FFE14D as a highlighter swipe** that draws across stressed words (it animates left to right). This ties to the existing covers and is clearly not red serif. |
| **Type** | Bold condensed sans for headlines (already on the covers), plus mono for labels and data. No serif. |
| **HUD** | Top-left: `TEST 014 · CLAUDE CODE`. Top-right: one live readout (`TIME 0:00 → 4:12`, `COST $0.00`, `VIEWS 176`). The test number escalates across the series, so it doubles as a follow reason. |
| **Signature payoff** | A **verdict stamp** at the end of every test: `WORTH IT` / `OVERHYPED` / `USE THIS`. It's repeatable, screenshot-able and great as a cover. |
| **Middle zone** | **Real screen recordings in a clean device frame**, zoomed and highlighted on the exact line that matters. Illustrations only where no real UI exists. |
| **Kai** | A real-looking cutout, bottom-left or bottom-right (not centred, so UI gets the width). He reacts, points and leans in on the verdict. The themed mic changes with the season or series. |
| **Covers** | The cover is the verdict frame: `TEST 014` + a 3–5 word result + the stamp. One template for the whole grid. |
| **Sound** | Whoosh on panels, pop on stamps, a printer or receipt "tick" for the readout, a boom on the verdict. No music baked in. |
| **On-screen text** | **Keywords and headlines only, not a full transcript.** You plan to add standard captions in-app, and a full word-by-word transcript at the top would double up with them. *(Note: the "Slop vs Viral" spec has the full VO building at the top. Let's decide whether to keep that or switch to keywords only before I build it.)* |

## Phase 5 — Production with the tools we already have

| Build with | What | Why |
|---|---|---|
| **Remotion (repo template)** | Grid background, HUD, highlighter swipes, verdict stamps, device frames, counters, zoom/highlight on screen recordings, covers. All timed from `words.json`. | Repeated every video, so build once and drive it with data. |
| **Real screen recording** (QuickTime/OBS, 60fps, 1080-wide) | Claude, Claude Code, HeyGen and Higgsfield UIs and outputs. | This is the proof. Remotion handles the zoom, speed ramps and highlights on top. |
| **HeyGen** | Kai VO once → lip-synced angles (multicam) → green-screen cutout. | Existing pipeline, unchanged. |
| **Higgsfield** | Kai stills and new angles, seasonal mics, and only the b-roll that can't be a real recording. | Fewer mood shots, so fewer credits. |
| **Captions.ai** | Quick talking-head-only videos (dilemmas, hot takes), and optional subtitles at posting. | Fastest option when no template is needed. |
| **Claude Code automation** | whisper → `words.json`; script → `scenes.json` (one event per stressed word); render; **auto self-check** (ffmpeg `freezedetect` for anything still >1.2s, an event-vs-word timing diff, a first-frame check); a contact sheet; and a `manifest.json` row. | Turns the Section 9 rules into a pass/fail gate, not a judgement call. |

**Template plan:** one `TestBench.tsx` with variants (System Giveaway, Tested-in-24h, Comparison, Dilemma), so every format shares the same look.
